# LSH 算法实现、优化与高维数据对比分析报告

本实验的全部代码开源在 <https://github.com/Nictheboy/college-alg-2-bbf>。

## 1. 背景与目的

本项目旨在实现并评估多种近似最近邻 (ANN) 搜索算法在不同维度数据上的性能。我们最初的目标是实现包括局部敏感哈希 (LSH) 在内的多种方法，并对它们进行比较。在实现过程中，我们重点对LSH算法的哈希机制进行了多次迭代和优化尝试，以期在保持较高召回率的同时提升其在高维数据上的查询效率。实验将各种算法与传统的暴力搜索、标准K-D树精确搜索以及K-D树的近似版本 (Best Bin First, BBF) 在构建时间、查询速度、准确性及空间开销方面进行了综合比较，特别关注了LSH变体在维度K=100, 500, 1000的数据上的表现。

## 2. 算法演进与实现细节

本次实验对比了以下几种核心的最近邻搜索算法。其中，LSH算法经历了显著的演进。

### 2.1 基准算法

*   **暴力搜索 (BruteForce)**：
    *   作为最基础的精确搜索方法，它通过计算查询点与数据集中每一个点的实际距离来找到最近邻。此方法保证100%准确，但其 O(N\*D) 的查询复杂度使其在大数据集和高维度下性能较差，主要用作正确性验证和性能基准。

*   **K-D树及其变体 (KDTree\_Exact, KDTree\_Approx\_BBF200)**：
    *   这些是基于空间划分的经典方法。虽然本次报告的重点是LSH，但实验中我们保留了K-D树（精确搜索）和BBF（`t=200`的近似搜索）作为参照组，它们的数据将被包含在结果对比中，以提供更全面的性能图景。

### 2.2 局部敏感哈希 (LSH) 的探索历程

LSH的核心思想是设计一族哈希函数，使得原始空间中距离相近的点以较高概率映射到相同的哈希桶中，而距离较远的点则以较高概率映射到不同的桶。我们的实现围绕参数 `l`（哈希表的数量）和 `k`（构成每个哈希码的独立哈希函数/投影的数量）展开，实验中固定为 `l=4`, `k=5`。

#### 2.2.1 初步尝试：基于随机投影的LSH

我们首先实现了标准的随机投影LSH。其主要步骤如下：
1.  **生成随机超平面**：为 `l` 个哈希表中的每一个，生成 `k` 个独立的 `D` 维随机向量（超平面法向量）。向量的每个分量从标准正态分布中抽取。
2.  **计算哈希码**：对于一个 `D` 维数据点，将其与上述每个随机向量进行点积运算。点积结果的符号（正或负）决定了该投影下的1比特哈希值（例如，正为1，负为0）。将 `k` 个这样的比特串联，形成一个 `k`-bit的哈希码。
3.  **构建哈希表**：将数据点（或其索引）存入其哈希码对应的桶中。
4.  **查询**：为查询点计算哈希码，检索对应桶中的所有候选点，然后计算这些候选点与查询点的精确距离，返回最小者。

然而，在对低维数据（例如K=8，来自`data/`目录的原始测试集）进行初步测试时，此版本的LSH性能远未达到预期：
*   **查询效率低下**：其查询时间甚至显著慢于暴力搜索。
*   **候选集膨胀**：`k=5` 意味着每个哈希表只有 `2^5 = 32` 个桶。对于包含10万个点的数据集，平均每个桶内有超过3000个点，导致候选集非常庞大，后续的精确距离计算成为瓶颈。
*   **浮点运算开销**：大量的点积运算涉及浮点数，也带来了不可忽视的计算成本。

这些观察促使我们反思并寻求更适合当前实验框架和数据特点的LSH哈希机制。

#### 2.2.2 优化迭代：整数求和与奇偶性哈希 (LSH\_SumParity\_l4\_k5)

考虑到标准随机投影LSH在低维和特定参数下的不佳表现，以及浮点运算的潜在开销，我们设计并实现了一种基于整数运算的启发式LSH变体。其核心思想是用更简单、计算成本更低的整数操作来模拟"投影"和"哈希"的过程：

1.  **定义"求和投影"参数**：
    *   代替随机超平面，我们为每个基础哈希函数（共 `l*k` 个）定义了一组整数参数：`start_dim` (随机选择的起始维度) 和 `num_components` (随机选择的从`start_dim`开始的连续维度数量，本实验中设为1到5之间)。这些参数在LSH结构构建时一次性随机生成并存储。
    *   **理论联系**：计算数据点 `P = (c_1, c_2, ..., c_D)` 在 `start_dim` 开始的 `num_components` 个连续分量的和，即 `S = c_{start_dim} + c_{start_dim+1} + ... + c_{start_dim+num_components-1}`，这在数学上等价于数据点 `P` 与一个特殊的投影向量 `R` 进行点积运算。该投影向量 `R` 是一个稀疏向量，其在 `start_dim` 到 `start_dim+num_components-1` 的维度上的分量为1，而在其他所有维度上的分量为0。因此，`S = P · R`。

2.  **计算整数哈希码**：
    *   对于一个数据点（其坐标为整数向量）：
        *   对其 `k` 个基础哈希函数，分别根据上述方法计算出对应的和 `S`。
        *   该基础哈希函数的1比特输出由这个和 `S` 的**奇偶性**决定（例如，奇数和映射为比特1，偶数和映射为比特0）。
    *   将这 `k` 个比特串联起来，形成最终的 `k`-bit哈希码。

3.  **构建与查询**：
    *   哈希表的构建和查询流程与标准LSH类似：数据点根据其整数哈希码存入桶中；查询点也计算其整数哈希码，检索候选，并进行精确距离排序。

这种"整数求和奇偶性哈希"的LSH变体 (在结果中标记为 `LSH_SumParity_l4_k5`) 的主要优势在于：
*   **计算效率**：完全避免了浮点运算，哈希码的计算速度极快。
*   **实现简单**：逻辑相对直接。

其"局部敏感性"则依赖于一个经验性的假设：如果两个点在原始空间中是近邻，那么它们坐标向量中的随机子段（由 `R` 向量定义）的投影值（即和 `S`）在奇偶性上表现出相似性的概率可能会比不相关的点更高。这是一种探索性的哈希策略，其有效性需要在不同维度和数据分布下通过实验来检验。

## 3. 实验设置

*   **数据集**:
    *   本次报告主要分析三大类高维数据集，分别位于 `data_100/`、`data_500/` 和 `data_1000/` 目录下。
    *   每个目录包含100个独立的文本文件（例如 `1.txt` 到 `100.txt`）。
    *   每个文件包含 `N` 个建树点和 `M` 个查询点，点的维度 `K` 分别为100、500和1000。根据生成脚本，通常 `N=1000`（建树点数量），`M=100`（查询点数量），点坐标为0到1000之间的随机整数。
    *   原始的K=8维数据 (`data/`目录) 的结果也一并列出作为参考，尽管这部分数据在报告中不作为主要分析对象。

*   **硬件与环境**:
    *   CPU: Apple M1 Pro
    *   RAM: 16GB
    *   操作系统: macOS Sonoma 14.4
    *   编译器: Apple clang version 15.0.0 (clang-1500.3.9.4)
    *   编译指令: `clang++ -std=c++17 -O2 main.cpp -o main` (或同等优化等级)

*   **评价指标**:
    *   **构建时间 (ms)**: 算法构建索引或内部数据结构的平均时间。
    *   **平均查询时间 (ms)**: 对单个查询点找到最近邻所需的平均时间。
    *   **准确率 (%)**: 定义为近似算法返回的最近邻点 `p_approx` 与真实最近邻点 `p_exact` 之间的距离 `dist(q, p_approx)` 与查询点 `q` 到真实最近邻的距离 `dist(q, p_exact)` 的比率小于等于1.05的查询所占的百分比。即 `(dist(q, p_approx) / dist(q, p_exact) <= 1.05)` 的比例。
    *   **平均距离比值**: 所有查询的 `dist(q, p_approx) / dist(q, p_exact)` 的平均值。该值越接近1，说明近似结果越接近真实结果。
    *   **空间开销**: 算法所占用的内存空间，以Bytes、KB或MB为单位。

*   **LSH 特定参数** (适用于 `LSH_SumParity_l4_k5`):
    *   哈希表数量 (`l`): 4
    *   每表哈希函数数量/哈希码长度 (`k`): 5
    *   `LSH_SumParity`中求和的连续分量数量: 在构建时为每个基础哈希函数随机选择1到5个。

### 4.1 维度对算法性能的普遍影响

从汇总数据可以看出，数据维度 `K` 的增加对所有算法的性能都产生了显著影响，尤其是在计算时间方面。
*   **构建时间**：随着维度从K=100增加到K=1000：
    *   BruteForce的构建时间（主要是数据加载和存储）变化不大，因为它几乎没有预处理。
    *   KDTree\_Exact和KDTree\_Approx\_BBF200的构建时间均有明显增长（K100约1.4ms -> K1000约4.9ms），这符合K-D树构建过程对维度敏感的特性，高维下寻找最优分割轴和进行数据划分更为耗时。
    *   LSH\_SumParity的构建时间也随维度增加而增加（K100约0.82ms -> K1000约1.03ms），但其增长幅度相对温和。这主要是因为其核心操作（随机选择求和参数和填充哈希表）的复杂度与维度D的直接关联度低于K-D树的构建。

*   **查询时间**：
    *   BruteForce的查询时间与维度D成正比增长（K100约28.8ms -> K500约137ms -> K1000约276ms），清晰地展现了其 O(N\*D) 的查询复杂度。
    *   KDTree\_Exact在高维下性能急剧下降。在K=100时，其查询时间（约29.4ms）与BruteForce相当，甚至略高。当维度升至K=500和K=1000时，其查询时间几乎与BruteForce完全一致，表明在高维空间中，K-D树的剪枝效率大大降低，趋向于遍历所有数据点，失去了其理论上的优势。这是"维度灾难"在K-D树上的典型体现。

### 4.2 近似算法在高维的表现

接下来我们重点分析两种近似算法 `KDTree_Approx_BBF200` 和我们改进的 `LSH_SumParity_l4_k5`。

*   **KDTree\_Approx\_BBF200 (BBF t=200)**:
    *   **查询时间**：BBF算法在所有测试维度上都展现了出色的查询速度。相较于精确K-D树，其加速效果在高维时尤为显著。例如，在K=1000时，BBF查询时间约为56ms，远低于精确K-D树和暴力搜索的约276ms。这得益于其限制检查节点数量（200个）的策略，有效避免了高维K-D树趋于全量扫描的问题。
    *   **准确率与距离比值**：有趣的是，BBF的准确率（1.05阈值内）随着维度的升高反而显著提升：K=100时约82.4%，K=500时提升至约99.5%，在K=1000时更是达到了接近完美的99.99%。相应的，平均距离比值也从K=100的1.0241逐渐降低到K=1000的1.0082，非常接近1。这表明在高维稀疏空间中，即使只检查固定数量（200个）的"最佳候选桶"中的节点，也极有可能找到非常接近真实最近邻的点。这可能是因为高维空间中，点与点之间的距离差异更为显著，稍微偏离最优路径就可能导致距离大幅增加，使得BBF的优先队列机制能更有效地将搜索导向正确的邻域。
    *   **构建时间与空间开销**：与精确K-D树基本一致，因为它们共享相同的树构建过程。

*   **LSH\_SumParity\_l4\_k5 (整数求和奇偶性LSH)**:
    *   **构建时间**：此LSH变体的构建时间在所有算法中表现最优，且随维度增长缓慢（K100约0.82ms -> K1000约1.03ms）。这完全符合预期，因为其哈希函数参数的生成和哈希表的填充过程计算复杂度较低，且与数据维度的耦合较松。
    *   **查询时间**：LSH的查询时间也表现出良好的可伸缩性。在K=100时（约6.2ms），略慢于BBF（约6.0ms）。但在K=500（LSH约19.3ms vs BBF约27.9ms）和K=1000（LSH约36.1ms vs BBF约56.1ms）时，LSH\_SumParity的查询速度均快于BBF。这显示了该LSH变体在更高维度下，通过哈希桶快速筛选候选集的能力开始显现优势。
    *   **准确率与距离比值**：
        *   在K=100维度下，LSH\_SumParity的准确率相对较低（约54.6%），平均距离比值也偏高（1.0484）。这说明在该维度和参数设置下，求和奇偶性哈希的局部敏感性可能不足以有效区分近邻，或者`k=5`的哈希码长度对于100维数据来说区分度不够，导致桶冲突较多或错误的近邻被检索。
        *   然而，非常引人注目的是，当维度上升到K=500和K=1000时，LSH\_SumParity的准确率大幅提升至接近100%（K500约98.1%，K1000约99.96%），平均距离比值也显著改善（K500约1.0185，K1000约1.0125）。这一现象表明，尽管"整数求和奇偶性"是一种启发式哈希，但在非常高的维度下，它似乎意外地获得了良好的区分度。高维空间中点的分布特性（例如，随机投影更可能将不相关的点分开）可能使得这种简单的哈希方法也能有效地将近邻映射到相同的桶中，或者说，非近邻被映射到同一个桶的概率因维度增加而降低了。
    *   **空间开销**：与K-D树系列算法大致相当，略高一点点，主要开销在于存储原始数据点和多个哈希表。由于`l`和`k`固定，哈希表结构本身的开销变化不大，主要随数据点数量N和每个桶内存储的索引数量变化。

### 4.3 综合讨论

在高维数据上（K=500, K=1000），传统的精确K-D树算法由于维度灾难，查询性能退化至与暴力搜索无异，失去了实用价值。相比之下，两种近似算法BBF和我们提出的LSH\_SumParity都表现出了显著的性能优势。

BBF算法在高维下表现出惊人的准确率恢复，查询速度也较快，是一种非常稳健的近似搜索方法。

我们设计的LSH\_SumParity变体，虽然在K=100时准确度不佳，但在K=500和K=1000维度下，不仅查询速度非常快（在K500和K1000均优于BBF），而且准确率也达到了非常高的水平。其极低的构建时间更是一大亮点。这表明这种简单的、基于整数运算的LSH哈希策略在高维空间中具有相当大的潜力，可能得益于高维特性某种程度上"弥补"了哈希函数本身的简单性。其性能的意外提升值得进一步探究，例如分析`k`值、`l`值以及求和分量数`num_components`对高维数据哈希效果的具体影响。

对于空间开销，所有基于索引的方法（KD-Tree, LSH）都比BruteForce需要更多的空间，这是存储索引结构的必然代价。三者之间的空间差异不大，在可接受范围内。
